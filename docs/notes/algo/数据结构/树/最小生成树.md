

# 最小生成树（MST）

## 引入

### **生成树的定义**

一个连通图的生成树是一个极小的连通子图，它包含图中全部的n个顶点，但只有构成一棵树的n-1条边。

<img src="https://pic3.zhimg.com/v2-a89c87ebaf244377c48db2516df35096_1440w.jpg" alt="img" style="zoom:80%;" />

很容易可以看出来，对于一个连通图，它的生成树就是不形成环的前提下，能够连接到所有点的一种树的雏形，看上面三个例子就能清晰明了。

### **生成树的属性**

- 一个连通图可以有多个生成树；
- 一个连通图的所有生成树都包含相同的顶点个数和边数；
- 生成树当中不存在环；
- 移除生成树中的任意一条边都会导致图的不连通， 生成树的边最少特性；
- 在生成树中添加一条边会构成环。
- 对于包含n个顶点的连通图，生成树包含n个顶点和n-1条边；
- 对于包含n个顶点的无向完全图最多包含n^(n-2)颗生成树

## 正题

> 对于生成树的概念搞明白了以后，最小生成树顾名思义就是在连通图延伸出的几种生成树中，找到权值之和最小的那种，就是最小生成树

### 实现方法

实现最小生成树的经典算法有两个，克鲁斯卡尔（Kruskal），普里姆（Prim）算法

#### Kruskal

克鲁斯卡尔算法是一种使用贪婪方法的最小生成树算法，该算法初始将图视为森林，图中的每一个顶点视为一颗单独的树，一棵树只与它的邻接顶点中权值最小且不违反最小生成树属性（不构成环）树之间建立连边。

##### 判断环的方法

要判断添加一条边 X-Y 是否形成环，我们可以判断顶点X在最小生成树中的终点与顶点Y在最小生成树中的**终点是否相同**，如果相同则说明存在环路，否则不存环路，从而决定是否添加一条边。

所谓**终点**，就是将所有顶点按照从小到大的顺序排列好之后；某个顶点的终点就是"与它连通的最大顶点"。看下图，我们可以对图中顶点进行排序，排序后的顶点存放在一个数组中，每一个顶点则对应一个下标，同样的我们针对排序后的数组创建一个顶点的终点数组，初始时图中的每一个顶点是一棵树，每一个顶点的终点初始化为自身，我们用0来表示。

回到之前的算法执行过程，我们配合这个终点数组再来一次。

同样，若选择1-&gt;2（1的终点为6，2的终点为6，终点相同会形成环）舍弃

以此类推，其实运用到了不断更新端点，并把旧端点的终点不断往新的结点带，不断累前，这样就能和轻松地看看两个节点的终点是否一致（因为都在往前更新，而不是留在旧的地方，省去了并查集的merge操作）

##### 代码

```c++
#include<iostream>
#include<cstring>
#include<algorithm>
#include<climits>
#include<cstdio>
using namespace std;
const int N=1e6+2;
int n,m,fa[N];
struct node{
	int x;
	int y;
	int z;
}edge[N];
bool cmp(node x,node y){
	return x.z<y.z;
}
int find(int i){
	return i==fa[i]?fa[i]:(fa[i]=find(fa[i]));
}
int main(){
	std::cin>>n>>m;
	for(int i=1;i<=m;i++) std::cin>>edge[i].x>>edge[i].y>>edge[i].z;
	sort(edge+1,edge+1+m,cmp);
	for(int i=1;i<=n;i++) fa[i]=i;
	int sum=0;
	for(int i=1;i<=m;i++){
		int p=find(edge[i].x);
		int q=find(edge[i].y);
		if(p==q) continue;
		fa[p]=q;
		sum+=edge[i].z;
	}
	int ans=0;
	for(int i=1;i<=n;i++){
		if(i==fa[i]) ans++;
	}
	if(ans>1){
		std::cout<<"orz";
		return 0;
	}
	else std::cout<<sum;
	return 0;
}
```

#### Prim

普里姆算法跟克鲁斯卡尔不太一样，一个是从边入手，如果不生成环就加入，一个是从点出发，每次往附近找一个最近的点加入

它将顶点分为两类，一类是在查找的过程中已经包含在生成树中的顶点（假设为 A 类），剩下的为另一类（假设为 B 类）。

对于给定的连通网，起始状态全部顶点都归为 B 类。在找最小生成树时，选定任意一个顶点作为起始点，并将之从 B 类移至 A 类；然后找出 B 类中到 A 类中的顶点之间权值最小的顶点，将之从 B 类移至 A 类，如此重复，直到 B 类中没有顶点为止。所走过的顶点和边就是该连通图的最小生成树。

##### 代码

```c++
#include<iostream>
#include<cstdio>
#include<cstring>
#include<algorithm>
#include<climits>
using namespace std;
const int N=1e6+2;
int x,y,z,n,m,g[6000][6000],dist[N],vis[N];
int prim(int pos){
	int sum=0;
	dist[pos]=0;
	for(int i=1;i<=n;i++){
		int cur=-1;
		for(int j=1;j<=n;j++){
			if(!vis[j]&&(cur==-1||dist[j]<g[cur][j])) cur=j;
		}
		if(dist[cur]>=0x3f3f3f3f) {
			std::cout<<"orz";
			return 0;
		}
		vis[cur]=1;
		sum+=dist[cur];
		for(int k=1;k<=n;k++){
			if(!vis[k]) dist[k]=min(dist[k],g[cur][k]);
		}
	}
	return sum;
}
int main(){
	memset(dist,0x3f,sizeof(dist));
	memset(g,0x3f,sizeof(g));
	std::cin>>n>>m;
	for(int i=1;i<=m;i++){
		std::cin>>x>>y>>z;
		g[x][y]=z;
		g[y][x]=z;
	}
	int value=prim(1);
	std::cout<<value;
	return 0;
}
```

> 注意，这时邻接矩阵的写法，很受限，只能在n&lt;500才能使用，一大就会内存超限！qwq

##### 链式前向星优化

```c++
#include<iostream>
#include<cstdio>
#include<cstring>
#include<algorithm>
#include<climits>
using namespace std;
const int N=1e6+2;
struct node{
	int v,w,next;
}e[N<<1];
int x,y,z,n,m,dist[N],vis[N],cnt,head[N];
inline void add(int u,int v,int w){
	e[++cnt].v=v;
	e[cnt].w=w;
	e[cnt].next=head[u];
	head[u]=cnt;
}
int prim(int pos){
	int sum=0;
	dist[pos]=0;
	for(int i=1;i<=n;i++){
		int cur=0;
		for(int j=1;j<=n;j++){
			if(!vis[j]&&(dist[j]<dist[cur])) cur=j;
		}
		if(dist[cur]==0x3f3f3f3f) {
			std::cout<<"orz";
			exit(0);
		}
		vis[cur]=1;
		sum+=dist[cur];
		for(int k=head[cur];k;k=e[k].next){
			if(!vis[e[k].v]&&e[k].w<dist[e[k].v]) dist[e[k].v]=e[k].w;
		}
	}
	return sum;
}
int main(){
	memset(dist,0x3f,sizeof(dist));
	std::cin>>n>>m;
	for(int i=1;i<=m;i++){
		std::cin>>x>>y>>z;
		add(x,y,z);
		add(y,x,z);
	}
	int value=prim(1);
	std::cout<<value;
	return 0;
}
```

关于链式前向星的理解，在最短路有描述，这道题用不到最短路，就只需要把dist[e[k].v]更新为当前最短边的权值就好了，后面直接判断，而最短路是要加上全面累计的边权，然后更新。。。



## 区别

 **选择Prim算法当：**

- 图是稠密的（边数接近完全图）
- 可以确定一个合理的起始点
- 需要在线处理图（边动态增加）
- 内存充足，可以存储整个图的邻接矩阵

  **选择Kruskal算法当：**

- 图是稀疏的（边数远少于完全图）
- 没有明显的起始点优势
- 需要并行处理
- 边已经预先排序或可以离线排序
- 内存有限，适合边列表表示
