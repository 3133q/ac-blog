# 卡超时应对技巧

> 目前大多数题目会直接给出t组数据，然后去求解这t组，这样出的一个好处是你需要在每一组处理的时候清空所有数组，变量，不清的话就会出问题，导致全盘皆输，还有就是输入输出缓冲区的问题，会卡时间

c++默认的输入输出流（cin/cout）为了追求“兼容性”和“交互性”，会牺牲极大的性能，所以当我们面对几十万级别的数据（1e5~1e6）输入输出数据时，c++默认的I/O耗时会高达0.5秒到1秒，所以，我们需要这三句利器！

```c++
ios::sync_with_stdio(0);
cin.tie(0);
cout.tie(0);
```

## 1. ios::sync_with_stdio(0); 

解除c/c++核心同步，默认情况c++的cin/cout和C语言的scanf/printf默认是同步的，意味着程序为了保证输入输出的顺序不乱，会在底层频繁同步两者的缓冲区，操作开销很大，加上这句相当于关闭了c++流的同步，使用独立且极快的缓冲区

## 2.cin.tie(0)

- 为了保证用户能在屏幕上看到“请输入您的名字”这句话后才输入，C++ 规定：**每次执行 cin 之前，必须强行刷新（flush）一次 cout 的缓冲区，把数据推到屏幕上。**
- **在算法题中的灾难**：算法题都是文件输入输出，根本不需要交互。如果你的代码在循环里交替进行读和写（比如边读边输出），cin 会不断地强迫 cout 刷新缓冲区。频繁的硬盘/屏幕写操作（flush）是极其极其缓慢的。
- **加上这行代码（参数填 0 或 NULL）后**：解除了 cin 对 cout 的绑定。执行 cin 时不再强制刷新 cout，cout 只有在自己的缓冲区满了，或者程序结束时才会一并输出。这极大地减少了底层 I/O 调用的次数。
