##### 分数取模

其实分数取模就是乘法逆元的应用，关于乘法逆元，可以看看这个 [乘法逆元.md](D:\C语言\算法笔记\数学\乘法逆元.md) 

以 a/b 举例

先给出结论：由费马小定理可知，在模数m是质数，且b不是m的倍数的情况下，有：
$$
\frac{a}{b}\space mod\space m=a\times b^{m-2}\space mod\space m
$$
也就是说，在mod m的意义下，
$$
\frac{1}{b}=b^{m-2}\space mod\space m
$$
例如，在mod 998244353的情况下，
$$
\frac{2}{3}=2\times 3^{9982443531}\space (mod\space 998244353)
$$
这是因为998244353是一个质数，且3不是998244353的倍数

Ps.现在算法竞赛取模的数其实也是有讲究的

> 一般都用1e9+7 或者 998244353 ，因为他俩都是质数，对于费马小定理不容易不适配，从而出现精度差问题。

对于乘法逆元，本就是将 a除以b 转化为 a乘以b的逆元，这样一来计算结果是正确的，同时将分数（小数）的运算转为了整数方面的运算，从而避免了小数可能造成的精度问题。

#### 正题

首先，利用显示器间的独立，分别求出显示器显示0-9每个数字的概率，有了概率，就可以进一步求出某个四位数的概率，直接相乘就好啦，这里有一个巧思，不用数学的直接A+B=C，只要举一个A，然后B=C-A，因为C已知嘛，所以这两个求出来后，P(C)=P(A)*P(B)

![image-20260206151353281](/images/image-20260206151353281.png)

看这个，给七根灯管标个号，比如说要表示2，是不是点亮1 3 4 5 7就可以了，也就是说2的情况，1 3 4 5 7亮，而2 5 6灭，正好相反，有没有想到啥，二进制呀！！！

用二进制01表示灭与亮，所以说2就是1001101，以此类推。。。

int num[] = {0b1110111, 0b0100100, 0b1011101, 0b1101101, 0b0101110, 0b1101011, 0b1111011, 0b0100101, 0b1111111, 0b1101111};

void solve() {
    int C;
    cin >> C;
    vector<Z> p(7);
    for (int i = 0; i < 7; ++i)
        cin >> p[i], p[i] /= 100;
    vector<Z> q(10, 1);
    for (int i = 0; i <= 9; ++i) {
        auto msk = num[i];
        for (int j = 0; j < 7; ++j) {
            if (msk & (1 << j))
                q[i] *= p[j];
            else
                q[i] *= 1 - p[j];
        }
    }
    vector<Z> P(10000);
    for (int a = 0; a < 10; a++) {
        if (q[a] == 0)
            continue;
        for (int b = 0; b < 10; b++) {
            if (q[b] == 0)
                continue;
            for (int c = 0; c < 10; c++) {
                if (q[c] == 0)
                    continue;
                for (int d = 0; d < 10; d++) {
                    if (q[d] == 0)
                        continue;
                    int N = a * 1000 + b * 100 + c * 10 + d;
                    P[N] = q[a] * q[b] * q[c] * q[d];
                }
            }
        }
    }
    Z ans = 0;
    for (int i = 0; i <= C; ++i) {
        int j = C - i;
        if (C >= 0)
            ans += P[i] * P[j];
    }
    cout << ans << endl;
}

> Ps.这道题一开始想太简单了，直接靠猜，两两异或一下，然后多少个符合直接2的几次方。。。

#### 思路

其实我们仔细想想可以知道，不一定是两个之间，只要一组（一个区间）内的所有数sum=or，即可以满足，所以这里很巧妙，用到了线性dp，前缀和优化。

因为你可以想想  1 2 3 4 ....  n-1 n

我对前面的数进行改变（就是异或）这样对后面的数总没有影响吧，所以我们可以从前往后推理，考虑[1,i]这个子区间，替换的合法方案数，则转移我们向前找所有 j ，满足：[j+1,i] 这一段数字和等于或，对于这样的 j ，可以执行转移
$$
f_{i}:=f_{i}+f_{j}
$$

##### 理解

你可以这样想，我们找的j其实就是最左端能满足的区间端点，因为区间是以i结尾的，所以我们要找一个最靠左的L，满足[L,i]这一段区间的所有下标都可以作为上述的j，所以得用累加，就是说，考虑比L更右的端点的时候，就得累加上前面的种数，类似于前缀和的思想，便于优化！

#### 关于实现

对于如何知道sum=or这个问题，其实可以积累积累（感觉位运算这里很多东西都得靠经验垒起来），满足这个，其实就是二进制没有交集（&的计算结果为0），因此我们向前找一个二进制没有交集的最远位置即可，这一步如果一个个跳，数据大了可能会超时，所以我们跳过0，因为0没有意义，所以采用之前kmp的pre数组的方法，这样压缩时间复杂度到log次，非常方便。。

#### 代码

```c++
#include<bits/stdc++.h>
using namespace std;
const int N=998244353;
long long t,n;
void solve(){
    long long a[200001],dp[200001],pre[200001],ss[200001];
    std::cin>>n;
    for(int i=1;i<=n;i++) std::cin>>a[i];
    int s=0;
    for(int i=1;i<=n;i++){
        pre[i]=s;
        if(a[i]>0) s=i;
    }
    ss[1]=1;
    dp[1]=1;
    for(int i=1;i<=n;i++){
        int j=i,val=0;
        while(j>0&&(val&a[j])==0){
            val|=a[j];
            j=pre[j];
        }
        dp[i+1]=(ss[i]-ss[j]+N)%N;
        ss[i+1]=(ss[i]+dp[i+1])%N;
    }
    std::cout<<dp[n+1]<<'\n';
}
int main(){
    std::cin>>t;
    for(int i=0;i<t;i++){
        solve();
    }
    return 0;
}
```
